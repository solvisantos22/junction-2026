# Control, routing, and optimization evidence for AfterQuery

Research cutoff: **13 November 2026**. Scope: ColdChain and BatchPilot. This is a literature review and a proposal for an unbuilt falsification experiment; it contains no measured Junction result or project implementation.

**Assessment:** none of the reviewed sources establishes a large gap against today's full frontier coding agent with equal tools and information. Both ideas have credible classical references. ColdChain is easier to audit; BatchPilot better uses Manh's control background. The most consequential counterevidence is successful controller generation by recent models, plus very recent public process-operation environments. A hypothesis worth testing is failure to maintain constraints while making irreversible online commitments. Inability to calculate a route or recognize PID/MPC is insufficient grounds for choosing either idea.

## What planning evidence actually establishes

**Executable code substantially changes the comparison.** REPL-Plan, published at ACL in July 2025, combines interactive Python execution, error feedback, and recursive subtasks. In its harder WebShop setting, GPT-4o-mini with the same top-three examination strategy achieved 37% success with REPL-Plan versus 21% with THREAD. Expanding REPL-Plan to examine twenty candidates reached 52%, but that comparison changes the search strategy. The tasks concern shopping and household action sequences, rather than routing or thermal control; these results support testing the whole agent scaffold, not predicting a particular ColdChain gap. [Paper, §§2–3 and Table 3](https://aclanthology.org/2025.acl-long.994.pdf).

**Dynamic scheduling is relevant, but the reported deficit is modest and restricted.** DynaSchedBench, ICML 2026, evaluates online scheduling on a 70-instance subset. Its cross-model comparison uses direct dispatch, two demonstrations, and temperature zero: GPT-5 Mini has a 1.93% mean makespan gap relative to the best observed schedule; Qwen3-8B has 1.01%; the best fixed dispatch rule has 1.11%. Qwen3-8B is statistically indistinguishable from that rule. The tool condition offers only action inspection and a simulated completion-time proxy, not arbitrary code or optimization libraries. Richer structural context sometimes worsens performance, but “full information” means structural priors, not advance revelation of future events. This is evidence about a particular dispatch interface, not a demonstrated frontier coding-agent failure. [Paper, §§5–7, Tables 5–6, Appendix J](https://arxiv.org/html/2605.27566v1).

## ColdChain: strong references, a vulnerable difficulty claim

The EURO Meets NeurIPS routing competition provides a particularly useful precedent: an online variant reveals new orders at successive epochs, and a static solver is embedded in a dynamic dispatch strategy. Its official harness permits only information returned through `reset` and `step`, including documented auxiliary information. The supplied baseline uses HGS-VRPTW. This is a concrete example of an auditable causal reference, although arriving orders are not identical to the proposed disruption and perishability mechanics. [Competition paper](https://proceedings.mlr.press/v220/kool23a.html), [official harness and baseline](https://github.com/ortec/euro-neurips-vrp-2022-quickstart).

PyVRP is a practical solver candidate: its published package targets vehicle routing with time windows; current official documentation includes capacities, service durations, release times, heterogeneous vehicles, and duration limits. These capabilities do not automatically implement freshness decay or a custom disruption process. Pin a version and validate the exact encoding before treating its output as ground truth. A heuristic solution is a reference policy, not a proof of global optimality. [Package paper, January 2024](https://pubsonline.informs.org/doi/10.1287/ijoc.2023.0055), [official repository](https://github.com/PyVRP/PyVRP).

SVRPBench, NeurIPS 2025, adds stochastic congestion, delays, accidents, and heterogeneous time windows to routing instances. It evaluates classical methods and neural routing solvers, including attention-model and POMO approaches; those are not general language-model agents. Its value here is a precedent for grounded disturbance distributions and repeated stochastic evaluation, rather than evidence that an LLM will fail. [Paper, §§3–5](https://proceedings.neurips.cc/paper_files/paper/2025/file/ad0e5a0e026f1b0ff259140564d18680-Paper-Datasets_and_Benchmarks_Track.pdf).

**Our inference:** eight deliveries may be too easy once code is available. With fixed depot endpoints and each delivery served once by either of two labelled vehicles, all static route partitions and orders fit within `8! × 9 = 362,880` permutation-and-split candidates before pruning. This is a counting argument, not a runtime measurement; optional deliveries, waiting, and time-dependent travel alter the optimization. Nevertheless, an agent-generated enumerator could erase a gap attributed merely to combinatorial complexity.

The interesting question is whether the agent replans correctly after commitments: a vehicle already travelling cannot teleport, capacity already consumed cannot be retrospectively reassigned, and expired goods cannot become fresh again. Any claimed novelty should therefore concern the tested combination of online commitments and verified outcomes. “Routing with time windows and disturbances” already has substantial prior art.

## BatchPilot: distinguish control from controller generation

The official do-mpc CSTR example provides a credible physical reference: reaction and heat-transfer equations, separate reactor and jacket temperatures, bounded inputs, uncertain parameters, and a loop that solves MPC again after each observed state. It assumes direct measurement of all states. Its reactor-temperature bound is implemented as a **soft** constraint, so copying the example would not establish strict thermal safety. It is a continuous reactor example, not a validated finite-batch recipe. [Official model, constraints, estimator, and closed-loop example](https://www.do-mpc.com/en/latest/example_gallery/CSTR.html).

**Recent controller synthesis is strong counterevidence.** CoDyControlBench, an August 2026 preprint, evaluates generated PID/SMC controller code across 132 plant configurations. GPT-5.5 at high reasoning obtains 94.8% ± 0.8% design success under Fixed-3: choose the best successful controller from exactly three feedback-guided attempts, averaged over three independent runs. The model receives a code template and plant equations. Success requires settling within a ±2% band, but allows up to 100% overshoot. This tests synthesized feedback controllers in simulation, not a language model selecting every actuator update. It also does not establish success under tight irreversible batch-quality constraints or an MPC comparison. [Paper, §§II-B–D and Table I](https://arxiv.org/html/2608.07004v1).

**A genuine process example already uses a coding model.** A July 2026 gas-preheater study uses GPT-5.4 with medium reasoning to generate, execute, validate, and repair a complete PI/feedforward control-design pipeline. Bayesian optimization improves its tracking objective by approximately 26.5% over the initially generated controller, using 55 evaluations on a fixed scenario. This is one process, one model, and one end-to-end run; the authors explicitly reject interpreting that improvement as a comparison with a manually designed controller. It nevertheless demonstrates the exact escape route our benchmark must permit: generate a conventional controller and let code run the feedback loop. [Paper, §§IV–VI](https://arxiv.org/html/2607.21292v1).

**Supervisory recovery is also established prior art.** “From detection to action,” published in Journal of Process Control in 2026, evaluates GPT-4o-mini and GPT-4.1-mini on a simulated batch mixing module and a CSTR regulated by PID. Agents retrieve plant knowledge, propose recovery paths or setpoint adaptations, and use simulation plus deterministic validation. The final article explicitly limits its conclusions to matched plant/twin models and fault configurations; model mismatch and sensor-noise robustness are not evaluated. These are supervisory decisions above low-level feedback, not replacement of the controller. [Article and limitations](https://doi.org/10.1016/j.jprocont.2026.103855), [official reproducibility artifact](https://github.com/AISL-at-Imperial-College-London/ctrl-alt-recover).

**The closest new novelty warning is OperAItor.** Submitted on 3 November 2026, it supplies a reactor/distillation environment with PI loops, alarms, protective functions, and twenty fault scenarios. It evaluates GPT-5 nano and small open models with alternative action validators. The digital twin clones the true current state/model but excludes subsequently scheduled events. All reported decisions pause the simulation clock, and the main campaign has one run per model–validator–scenario combination. Its chemistry and economics are benchmark assumptions. It is valuable prior art for auditable operation and recovery, but neither a real-time result nor a current unrestricted frontier-agent comparison. [Preprint, §§4–8 and limitations](https://arxiv.org/pdf/2611.05179), [official repository](https://github.com/AISL-at-Imperial-College-London/operAItor).

## Comparison and recommended references

The judgments below are our inferences from the reviewed work, not observed prototype results.

| Question | ColdChain | BatchPilot |
|---|---|---|
| Credible starting reference | Exact search on the small currently known instance; PyVRP/HGS as a second check | Causal receding-horizon controller; tuned PID as a simpler baseline |
| Most plausible agent escape | Generate a route enumerator and rerun after events | Generate a feedback controller or MPC wrapper |
| Where a remaining gap might occur | Commitments, timing, state accounting, disruption recovery | Delayed actuation, terminal quality, constraint margins, recovery |
| Build risk | Lower; discrete transitions are easier to inspect | Higher; dynamics, units, integration, and feasibility need validation |
| Novelty pressure | Established dynamic/stochastic VRP | Recent controller synthesis and OperAItor directly overlap |
| First rejection condition | Code-assisted replanning reliably matches reference | Agent-generated controller reliably finishes acceptable batches |

For ColdChain, use the EURO harness as the fairness precedent and a small exact optimizer as an independent feasibility check. For BatchPilot, use do-mpc for modelling conventions, CoDyControlBench for a strong synthesis baseline, and the two Imperial process-operation artifacts for novelty comparison. Do not reproduce their full plant complexity for a weekend experiment.

## Smallest convincing, still-unbuilt experiment

1. **Attempt to erase the gap first.** Test one public nominal episode and one public disrupted episode, with three independent runs of the strongest available coding agent. Explicitly invite code, solvers, persistent state, and controller generation. Include a scaffolded run that points out the appropriate optimization/control family. A gap that disappears with that hint is weak evidence for this challenge.
2. **Equalize information.** Publish equations, units, constraints, current observations, and disturbance distributions. If the reference sees jacket temperature, queue contents, exact parameters, or a prediction model, the agent gets them too. Neither may see the future disturbance seed or event schedule. Record which quantities are measured, estimated, or assumed. A hindsight oracle may be a labelled diagnostic upper bound, never the competitive reference.
3. **Separate feedback from open-loop planning.** Compare a fixed initial plan, a simple feedback policy, the reference, and the agent. Permit the agent to submit executable feedback logic. This identifies whether success depends on feedback, a particular solver, or reliable orchestration.
4. **Declare computation and time semantics.** Start with a paused simulation clock and explicit total token/compute budgets. If reaction latency becomes part of the hypothesis, add a separately reported condition with a physically motivated deadline and a budget sweep. Disclose reference preparation, inference latency, solver time, and timeout behavior.
5. **Evaluate outcomes, then scale only if warranted.** Check completed deliveries or acceptable batches, irreversible violations, terminal score, and computation. Score do-nothing and stop-early policies at the same terminal horizon. If the initial difference survives, freeze the environment and reward, then evaluate unseen seeds; do not select the final instances because a particular model failed them. Three runs are a demonstration, not a precise reliability estimate.

10. [OperAItor, 3 November 2026](https://arxiv.org/pdf/2611.05179): printed pp. 10, 13, 23–25. Paused clock, causal twin scope, campaign limitations, and artifact availability.
